# Чек-лист подготовки сервиса CardHub к запуску в Продакшен (PRODUCTION_CHECKLIST.md)

Данный документ содержит исчерпывающий перечень шагов, настроек и доработок, необходимых для безопасного и юридически чистого вывода сервиса цифровых визиток «CardHub» в боевую эксплуатацию.

---

## 1. Транзакционная почта и подтверждение Email (SMTP)

- [x] **Подключен почтовый шлюз в РФ (Rambler SMTP)**:
  - Настроен транспорт `nodemailer` в `src/lib/email/sender.ts`.
  - Успешно протестирована отправка реальных писем через команду `npm run test:email <email>`.
- [x] **Отключен тестовый обход активации `devVerifyUrl` в коде**:
  - Из `src/app/api/auth/register/route.ts` и `RegisterForm.tsx` полностью удалена ссылка быстрой верификации. Активация аккаунта возможна только через реальное письмо.
- [ ] **Настроить DNS-записи для своего домена (когда будет подключен собственный домен вместо @rambler.ru)**:
  - **SPF**: разрешить отправку с серверов почтового провайдера.
  - **DKIM**: сгенерировать и прописать TXT-ключ цифровой подписи писем.
  - **DMARC**: настроить политику `v=DMARC1; p=quarantine;` или `p=reject;`.

  - Очищает всех тестовых пользователей, сессии, визитки, загруженные фото из `/public/uploads/`, сохраняя тарифы `REGULAR` и `PRO`.
- [ ] **Боевая ЮKassa и онлайн-чеки (54-ФЗ)**:
  - Заключить договор с ЮKassa и фискальным накопителем (Orange Data, Атол, МойСклад или сервис ЮKassa «Чеки»).
  - В `.env.production` прописать боевые ключи:
    ```env
    YOOKASSA_SHOP_ID=реальный_shop_id
    YOOKASSA_SECRET_KEY=live_секретный_ключ
    ```
    *(При наличии этих ключей код автоматически скроет тестовую кнопку «Оплатить в песочнице» и переведет все запросы на реальный шлюз).*
  - В файле `src/lib/payments/yookassa.ts` указать:
    - Реальный **ИНН** вашей организации/ИП (`inn: "7701234567"`);

  - В личном кабинете ЮKassa зарегистрировать URL входящего вебхука:
    `https://cardhub.ru/api/webhooks/yookassa` (события: `payment.succeeded`, `payment.canceled`).

## 3. Переменные окружения и криптографические секреты (`.env.production`)

- [ ] **`SESSION_SECRET`**:
  - Сгенерировать криптостойкий ключ длиной 64 байта:
    ```bash
    openssl rand -hex 64
    ```
  - Категорически запрещено использовать дефолтный fallback из кода.
- [ ] **`DATABASE_URL`**:
  - Задать строку подключения к боевой PostgreSQL с включенным SSL (`?sslmode=require`).
  - База данных обязана физически располагаться в ЦОД на территории Российской Федерации (требование 242-ФЗ).
- [ ] **`NEXT_PUBLIC_APP_URL`**:
  - Указать канонический боевой домен: `https://cardhub.ru` (обязательно с HTTPS).
- [ ] **`REDIS_URL`**:
  - Развернуть Redis / KeyDB для централизованного Rate Limiting (защита от перебора паролей и спама между всеми нодами Next.js).
- [ ] **`NODE_ENV=production`**:
  - Включает режим продакшена, оптимизирует бандл и выставляет флаги безопасности для Cookie (`Secure; HttpOnly; SameSite=Lax`).

## 5. Фоновые периодические процессы (Cron)

Скрипт регламентного обслуживания уже создан и готов к запуску: `npm run cron:maintenance`.

- [x] **Реализован модуль `src/lib/maintenance/service.ts` и CLI-команда**:
  ```bash
  # Проверочный запуск без изменения базы (dry-run):
  npm run cron:maintenance -- --dry-run

  # Боевой запуск:
  npm run cron:maintenance
  ```
- [ ] **Настроить системный планировщик на сервере (запуск ежесуточно в 03:00)**:
  - **Linux crontab**:
    ```bash
    0 3 * * * cd /var/www/cardhub && npm run cron:maintenance >> /var/log/cardhub-cron.log 2>&1
    ```
  - **Что выполняет за один прогон**:
    1. **152-ФЗ ст. 21 (Право на забвение)**: физически стирает (`hard delete`) данные и фотографии пользователей, удаленных более 30 дней назад.
    2. **Очистка сессий и токенов**: удаляет просроченные сессии и одноразовые email-токены.
    3. **Обслуживание подписок**: переводит истекшие подписки в `EXPIRED` и скрывает лишние визитки (сверх 1 на Free тарифе).
    4. **Аудит**: фиксирует факт проведения регламентных работ в `AuditLog`.

## 7. Инфраструктура, Reverse Proxy и Безопасность (DevOps)

- [x] **Готовый боевой Docker Compose (`docker-compose.prod.yml`)**:
  - Подготовлен стек из 5 контейнеров:
    1. `postgres:16-alpine` — боевая база данных с проверкой `healthcheck` (закрыта внутри сети `cardhub-net`, порты наружу не торчат);
    2. `redis:7-alpine` — кэш и распределенный Rate Limiter;
    3. `cardhub-app` — multi-stage сборка Next.js 16 в standalone-режиме под непривилегированным пользователем `nextjs`;
    4. `cardhub-nginx` — Reverse Proxy, SSL, Gzip, отдача статики и защита;
    5. `cardhub-certbot` — автоматическое продление бесплатных SSL-сертификатов Let's Encrypt каждые 12 часов.
  - Запуск стека в 1 команду:
    ```bash
    docker compose -f docker-compose.prod.yml up -d --build
    ```

- [x] **Конфигурация Nginx (`nginx/nginx.conf` и `nginx/conf.d/cardhub.conf`)**:
  - Включен Gzip для всех типов данных (JSON, CSS, JS, SVG, XML).
  - Принудительный редирект с `http://` на `https://`.
  - Проброшены заголовки реального IP (`X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`) для встроенного Rate Limiter и 152-ФЗ логов.
  - Ограничение размера загрузок: `client_max_body_size 5M;`.
  - Оптимизация статики:
    - `/uploads/` отдаются напрямую из volume с кэшем 30 дней;
    - `/_next/static/` кэшируются браузером на 1 год (`max-age=31536000, immutable`).
  - Скрипт быстрого выпуска SSL-сертификата Let's Encrypt:
    ```bash
    chmod +x scripts/init-letsencrypt.sh
    ./scripts/init-letsencrypt.sh cardhub.ru admin@cardhub.ru
    ```

- [x] **Резервное копирование базы данных с ротацией 7 дней**:
  - Подготовлены скрипты бэкапа со сжатием в gzip и расчетом SHA-256 контрольной суммы:
    - **Универсальный (Node.js/npm)**:
      ```bash
      npm run db:backup
      ```
    - **Для Linux crontab (`scripts/backup-db.sh`)**:
      ```bash
      # Запуск каждую ночь в 02:00:
      0 2 * * * cd /var/www/cardhub && ./scripts/backup-db.sh >> /var/log/cardhub-backup.log 2>&1
      ```
    - **Для Windows (`scripts/backup-db.ps1`)**:
      ```powershell
      .\scripts\backup-db.ps1 -DbUser postgres -DbName cardhub
      ```
  - Автоматически удаляет резервные копии старше 7 дней для экономии места на диске.

- [x] **Создание / Назначение первого аккаунта администратора (Bootstrap)**:
  - Реализован удобный скрипт назначения администратора:
    ```bash
    npm run admin:promote ваш-email@domain.ru
    ```
    *(Автоматически выдает роль `ADMIN`, подтверждает Email и активирует Pro-подписку для тестирования всех возможностей).*
  - Включить 2FA (TOTP) для учетной записи администратора в настройках `/dashboard/settings`.
