# Чек-лист подготовки сервиса CardHub к запуску в Продакшен (PRODUCTION_CHECKLIST.md)

Данный документ содержит исчерпывающий перечень шагов, настроек и доработок, необходимых для безопасного и юридически чистого вывода сервиса цифровых визиток «CardHub» в боевую эксплуатацию.

---

## 1. Транзакционная почта и подтверждение Email (SMTP)

Сейчас в режиме разработки ссылки подтверждения выводятся в JSON-ответе и в логах терминала. Для продакшена необходимо подключить реальную отправку писем.

- [ ] **Выбрать и зарегистрировать почтовый шлюз в РФ**:
  - Яндекс 360 для бизнеса, VK WorkMail, Mailopost или Unisender.
- [ ] **Настроить DNS-записи домена (Критично против попадания в спам)**:
  - **SPF**: разрешить отправку с серверов выбранного почтового провайдера.
  - **DKIM**: сгенерировать и прописать TXT-ключ цифровой подписи писем.
  - **DMARC**: настроить политику `v=DMARC1; p=quarantine;` или `p=reject;`.
- [ ] **Заполнить переменные окружения SMTP**:
  ```env
  SMTP_HOST=smtp.yandex.ru
  SMTP_PORT=465
  SMTP_SECURE=true
  SMTP_USER=no-reply@cardhub.ru
  SMTP_PASS=ваш_пароль_приложения
  SMTP_FROM="CardHub <no-reply@cardhub.ru>"
  ```
- [ ] **Отключить `devVerifyUrl` в коде**:
  - В файле `src/app/api/auth/register/route.ts` убедиться, что параметр `devVerifyUrl` отдается **только** при `process.env.NODE_ENV !== 'production'`.

## 2. Очистка тестовых данных и перевод оплат в боевой режим

- [ ] **Удалить тестовые данные из базы**:
  - Очистить таблицы тестовых пользователей, сессий, визиток и тестовых платежей:
    ```sql
    TRUNCATE TABLE "Payment", "Subscription", "CardEvent", "Report", "AuditLog", "CardField", "Card", "Membership", "Invitation", "Company", "Consent", "EmailToken", "TotpSecret", "Session", "User" CASCADE;
    ```
  - Заново накатить сиды базовых планов (`REGULAR` и `PRO`):
    ```bash
    npx prisma db seed
    ```
- [ ] **Боевая ЮKassa и онлайн-чеки (54-ФЗ)**:
  - Заключить договор с ЮKassa и фискальным накопителем (Orange Data, Атол, МойСклад или сервис ЮKassa «Чеки»).
  - В `.env.production` прописать боевые ключи:
    ```env
    YOOKASSA_SHOP_ID=реальный_shop_id
    YOOKASSA_SECRET_KEY=live_секретный_ключ
    ```
    *(При наличии этих ключей код автоматически скроет тестовую кнопку «Оплатить в песочнице» и переведет все запросы на реальный шлюз).*
  - В файле `src/lib/payments/yookassa.ts` указать:
    - Реальный **ИНН** вашей организации/ИП (`inn: "7701234567"`);
    - Вашу систему налогообложения (`sno: 1` — ОСН, `2` — УСН доход, `3` — УСН доход-расход);
    - Ставку НДС (для УСН обычно `vat_code: 1` — без НДС).
  - В личном кабинете ЮKassa зарегистрировать URL входящего вебхука:
    `https://cardhub.ru/api/webhooks/yookassa` (события: `payment.succeeded`, `payment.canceled`).

## 3. Переменные окружения и криптографические секреты (`.env.production`)

- [ ] **`SESSION_SECRET`**:
  - Сгенерировать криптостойкий ключ длиной 64 байта:
    ```bash
    openssl rand -hex 64
    ```
  - Категорически запрещено использовать дефолтный fallback из кода.
- [ ] **`DATABASE_URL`**:
  - Задать строку подключения к боевой PostgreSQL с включенным SSL (`?sslmode=require`).
  - База данных обязана физически располагаться в ЦОД на территории Российской Федерации (требование 242-ФЗ).
- [ ] **`NEXT_PUBLIC_APP_URL`**:
  - Указать канонический боевой домен: `https://cardhub.ru` (обязательно с HTTPS).
- [ ] **`REDIS_URL`**:
  - Развернуть Redis / KeyDB для централизованного Rate Limiting (защита от перебора паролей и спама между всеми нодами Next.js).
- [ ] **`NODE_ENV=production`**:
  - Включает режим продакшена, оптимизирует бандл и выставляет флаги безопасности для Cookie (`Secure; HttpOnly; SameSite=Lax`).

## 4. Хранилище медиафайлов (Аватары и обложки)

Сейчас файлы загружаются в локальную директорию `public/uploads`. В продакшене (особенно при контейнеризации или перезапуске нод) локальные файлы могут теряться.

- [ ] **Вариант А (Облачный S3 в РФ — рекомендуется)**:
  - Подключить S3-совместимое объектное хранилище (Selectel S3, Yandex Object Storage, Cloud.ru).
  - Настроить presigned upload URL или загрузку через серверный адаптер.
- [ ] **Вариант Б (Постоянный том Docker)**:
  - Если запуск на одном VPS через Docker: смонтировать внешний volume на каталог `/app/public/uploads`, чтобы загруженные фотографии сохранялись между перезапусками контейнеров.

## 5. Фоновые периодические процессы (Cron)

Скрипт регламентного обслуживания уже создан и готов к запуску: `npm run cron:maintenance`.

- [x] **Реализован модуль `src/lib/maintenance/service.ts` и CLI-команда**:
  ```bash
  # Проверочный запуск без изменения базы (dry-run):
  npm run cron:maintenance -- --dry-run

  # Боевой запуск:
  npm run cron:maintenance
  ```
- [ ] **Настроить системный планировщик на сервере (запуск ежесуточно в 03:00)**:
  - **Linux crontab**:
    ```bash
    0 3 * * * cd /var/www/cardhub && npm run cron:maintenance >> /var/log/cardhub-cron.log 2>&1
    ```
  - **Что выполняет за один прогон**:
    1. **152-ФЗ ст. 21 (Право на забвение)**: физически стирает (`hard delete`) данные и фотографии пользователей, удаленных более 30 дней назад.
    2. **Очистка сессий и токенов**: удаляет просроченные сессии и одноразовые email-токены.
    3. **Обслуживание подписок**: переводит истекшие подписки в `EXPIRED` и скрывает лишние визитки (сверх 1 на Free тарифе).
    4. **Аудит**: фиксирует факт проведения регламентных работ в `AuditLog`.

## 7. Инфраструктура, Reverse Proxy и Безопасность (DevOps)

- [ ] **Nginx / Caddy перед Next.js**:
  - Настроить SSL-сертификаты с автообновлением (Let's Encrypt или сертификаты Минцифры).
  - Настроить принудительный редирект с `http://` на `https://`.
  - Пробросить заголовки реального IP клиента:
    ```nginx
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    ```
    *(Необходимо для корректной работы встроенного Rate Limiter и фиксации IP в 152-ФЗ логах).*
  - Ограничить размер загружаемого тела запроса:
    `client_max_body_size 5M;`
- [ ] **Резервное копирование (Backups)**:
  - Настроить ночной автоматический дамп базы данных (`pg_dump` с шифрованием GPG) и копированием в изолированное географически удаленное хранилище.
- [ ] **Создание первого аккаунта администратора (Bootstrap)**:
  - Зарегистрировать владельца сервиса через обычную форму регистрации.
  - Выполнить команду назначения суперадминистратора:
    ```bash
    npx tsx -e "import { prisma } from './src/lib/prisma'; prisma.user.update({ where: { email: 'admin@cardhub.ru' }, data: { role: 'ADMIN' } }).then(() => console.log('Admin role granted!'));"
    ```
  - Включить 2FA (TOTP) для учетной записи администратора в настройках `/dashboard/settings`.
