# Чек-лист подготовки и запуска CardHub в Продакшен

В данном документе зафиксировано текущее состояние сервиса цифровых визиток **CardHub**: что уже **полностью реализовано и протестировано** на уровне кода, и что **осталось выполнить на внешнем уровне** для реального коммерческого запуска.

# Часть II. Что ОСТАЛОСЬ сделать для реального продакшена

Эти шаги выполняются на реальном сервере и во внешних сервисах (требуют покупки или заключения договоров):

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  1. VPS и    │ ──> │  2. Файл     │ ──> │ 3. ЮKassa и  │ ──> │  4. Запуск   │
│    Домен     │     │     .env     │     │    152-ФЗ    │     │   в Docker   │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

### Шаг 1. Аренда сервера (VPS) и покупка домена
- [ ] **Арендовать VPS в РФ**:
  - По закону 242-ФЗ персональные данные граждан РФ обязаны первично храниться в РФ.
  - Подойдет любой провайдер: Timeweb Cloud, Selectel, Beget, Cloud.ru (рекомендуемая конфигурация: 2–4 ядра CPU, 4–8 ГБ RAM, 40–60 ГБ SSD, ОС: Ubuntu 22.04 или 24.04 LTS).
- [ ] **Купить домен**:
  - Например, в зоне `.ru` (на Reg.ru, Beget, Timeweb — ~200–300 ₽/год).
- [ ] **Направить DNS-запись на сервер**:
  - В панели управления доменом создать `A`-запись: `@` и `www` указывают на публичный IP-адрес арендованного VPS.

---

### Шаг 2. Создание боевого файла переменных `.env` на сервере
Шаблон файла уже подготовлен в репозитории: `.env.production.example`. На сервере достаточно скопировать его в `.env` и сгенерировать 2 ключа:

- [ ] **Сгенерировать криптографические ключи**:
  ```bash
  # Секрет для сессий и кук (64 байта):
  openssl rand -hex 64

  # Ключ шифрования 2FA TOTP в базе (32 байта):
  openssl rand -hex 32

  # Пароль для базы данных PostgreSQL:
  openssl rand -hex 16
  ```
- [ ] **Заполнить переменные в `.env`**:
  ```env
  NEXT_PUBLIC_APP_URL="https://ваш-домен.ru"
  SESSION_SECRET="сгенерированный_ключ_64_байта"
  ENCRYPTION_KEY="сгенерированный_ключ_32_байта"
  POSTGRES_PASSWORD="сгенерированный_пароль_бд"
  DATABASE_URL="postgresql://cardhub:сгенерированный_пароль_бд@postgres:5432/cardhub?schema=public"
  ```

### Шаг 3. Платежи: ЮKassa и онлайн-касса (54-ФЗ)
- [ ] **Заключить договор с ЮKassa**:
  - Доступно для ИП или ООО (физлицам регулярный интернет-эквайринг не подключается).
- [ ] **Подключить онлайн-кассу (для отправки чеков в ФНС по 54-ФЗ)**:
  - Проще всего подключить встроенное решение ЮKassa «Чеки» (или интеграцию с Атол Онлайн / Orange Data).
- [ ] **Прописать боевые ключи и реквизиты**:
  - В `.env` на сервере:
    ```env
    YOOKASSA_SHOP_ID="боевой_shop_id"
    YOOKASSA_SECRET_KEY="live_секретный_ключ"
    ```
    *(При их указании тестовая кнопка «Оплатить в песочнице» автоматически скроется, а сервис перейдет на реальные платежи).*
  - В файле `src/lib/payments/yookassa.ts` указать:
    - Ваш реальный **ИНН** (`inn: "7701234567"`);
    - Систему налогообложения (`sno: 2` — УСН Доходы, `1` — ОСН, `3` — УСН Доходы минус расходы);
    - Ставку НДС (`vat_code: 1` — без НДС для УСН).
  - В личном кабинете ЮKassa настроить Webhook URL:
    `https://ваш-домен.ru/api/webhooks/yookassa` (события: `payment.succeeded`, `payment.canceled`).

### Шаг 5. Почта на собственном домене (SPF, DKIM, DMARC)
Сейчас в проекте настроен рабочий шлюз Rambler SMTP. Для запуска на боевом домене рекомендуется подключить корпоративную почту:
- [ ] **Подключить бесплатную почту для домена**:
  - Яндекс 360 для бизнеса, VK WorkMail или Mail.ru для бизнеса (создать ящик `noreply@ваш-домен.ru`).
- [ ] **Добавить DNS-записи у регистратора домена**:
  - **SPF** (TXT-запись): разрешает отправку с серверов почтового сервиса.
  - **DKIM** (TXT-запись): цифровой ключ защиты от подделки писем.
  - **DMARC** (TXT-запись): `v=DMARC1; p=quarantine;` (гарантирует, что письма подтверждения регистрации не попадут в спам).
- [ ] **Обновить настройки SMTP в `.env`**:
  ```env
  SMTP_HOST="smtp.yandex.ru" # или smtp.mail.ru
  SMTP_PORT="465"
  SMTP_SECURE="true"
  SMTP_USER="noreply@ваш-домен.ru"
  SMTP_PASS="пароль_приложения_от_почты"
  SMTP_FROM="CardHub <noreply@ваш-домен.ru>"
  ```

### Шаг 6. Команды первого запуска и Cron на боевом сервере
Когда сервер арендован и код склонирован, запуск занимает ровно 4 команды:

1. **Выпустить бесплатный SSL-сертификат Let's Encrypt**:
   ```bash
   chmod +x scripts/init-letsencrypt.sh
   ./scripts/init-letsencrypt.sh ваш-домен.ru admin@ваш-домен.ru
   ```
2. **Запустить стек в Docker**:
   ```bash
   docker compose -f docker-compose.prod.yml up -d --build
   ```
3. **Назначить своего первого администратора**:
   ```bash
   docker compose -f docker-compose.prod.yml exec app npm run admin:promote ваш-личный-email@домен.ru
   ```
4. **Добавить в системный планировщик сервера (`crontab -e`) 2 ночные задачи**:
   ```bash
   # Бэкап базы данных каждую ночь в 02:00 (хранение 7 дней):
   0 2 * * * cd /var/www/cardhub && ./scripts/backup-db.sh >> /var/log/cardhub-backup.log 2>&1

   # Регламентная очистка 152-ФЗ и подписок каждую ночь в 03:00:
   0 3 * * * cd /var/www/cardhub && docker compose -f docker-compose.prod.yml exec -T app npm run cron:maintenance >> /var/log/cardhub-cron.log 2>&1
   ```

После этого сервис работает полностью в автономном режиме: сам продлевает SSL, сам делает бэкапы, сам удаляет устаревшие персональные данные по закону и безопасно принимает пользователей.
